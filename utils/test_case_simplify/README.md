# 测试用例精简脚本（simplify_cases.py）

## 一、使用介绍

### 1.1 功能说明

`simplify_cases.py` 是 **NPUKernelBench 数据集测试用例的批量精简工具**。数据集中每个算子的测试用例文件（JSONL 格式）通常包含 30~150 条用例，直接用于 RL 训练代价过高。本脚本在**保持数值类型、属性分支、shape 形态与规模覆盖**的前提下，将每个算子的用例精简至 **10 条以内**，输出到 `<原文件名>_simple.json`。

### 1.2 使用方法

```bash
# 在算子测试用例所在目录（NPUKernelBench/src/）下运行脚本；
# 脚本扫描的是“当前工作目录”，与脚本自身位置无关
cd /path/to/ascendc-rl-datasets/NPUKernelBench/src
python3 ../../utils/test_case_simplify/simplify_cases.py
```

- 脚本自动扫描**当前工作目录**下**所有不含 `_simple` 的 `.json` 文件**，逐个生成对应的 `*_simple.json`（用例文件**无需**与脚本放在同一目录）。
- 新增算子时，只需把新的用例文件放入目录再次运行即可；脚本**无随机性、结果可复现**，已有算子的输出不会因重跑而改变。
- 运行结束后终端会打印汇总表：每个文件的用例数、精简后条数、保留的数值类型组合。

### 1.3 注意事项

1. **格式约定**：用例文件必须是 JSONL（每行一个 JSON 对象），顶层结构为 `{"inputs": [...]}`；输入条目的 `type` 仅支持 `tensor`（`shape` 字段）、`tensor_list`（`shapes` 字段，如 Cat 算子）、`attr`（`value` 字段）三种。遇到未知类型时脚本会在 **stderr 打印 WARNING**，该条目不参与特征提取——此时需在 `tensors_of()` 中补充对应解析。
2. **不足 10 条的文件**：去重后按**实际数量**保留，不会为了凑数而复制造假。
3. **纯 attr 算子**：无 tensor 输入的算子（如 `level2_22_HybridAttentionMaskPreparation`）也能正确处理，此时多样性完全由属性组合保证。
4. 脚本只读原始文件、写 `*_simple.json`，**不会修改或删除原文件**。

## 二、精简原则

精简分四步，核心思想是"**先保底边界、再贪心最大覆盖**"：

1. **精确去重**：按整行 JSON 规范化后去重，保留首次出现的用例。
2. **小样本直通**：去重后 ≤ 10 条的文件全量保留。
3. **锁定边界用例**：按用例总规模（所有输入张量元素数之和）锁定**最小、中位数、最大** 3 条，保证规模边界不丢失。
4. **贪心最大覆盖补足剩余名额**：每轮从候选中选出"能带来最多新特征覆盖"的用例，特征及权重如下，同分时偏好规模接近中位数的**主流用例**：

   | 特征 | 内容 | 权重 | 说明 |
   |---|---|---|---|
   | **数值类型组合** | 所有输入张量的 dtype 元组 | **100** | 最高优先，保证 float32 / float16 / bfloat16 / int 等全部覆盖 |
   | **属性取值组合** | attr 条目的 (name, value) | 10 | 覆盖 mode、dim、threshold 等语义分支 |
   | **rank 模式** | 各张量维度数组合 | 5 | 覆盖 1D ~ 4D 等 shape 形态 |
   | **规模档位** | 总元素数按 log2 分桶 | 2 | 兼顾小 / 中 / 大不同量级 |

## 三、可调整的参数

| 参数 | 位置 | 默认值 | 说明 |
|---|---|---|---|
| `K` | 脚本顶部常量 | `10` | 每个算子保留的最大用例数 |
| 特征权重 | `score()` 函数 | 100 / 10 / 5 / 2 | 四类特征的覆盖优先级，一般无需修改 |
| 中位数偏好系数 | `score()` 函数 | `0.1` | 同分时对主流规模的偏好强度，调大可进一步压缩极端 shape 入选概率 |
| 边界锁定策略 | `select()` 第 2 步 | 最小/中位/最大 | 如需保留其他分位点（如 P25/P75），可在此扩展 |

一般场景下**只需修改 `K`**，其余参数已按 NPUKernelBench 的数据分布调优。
